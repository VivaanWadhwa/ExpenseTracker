# Expense Tracking Web Application
## Technical Design Document

## Executive Summary

This document outlines the technical design for a privacy-focused expense tracking web application. The app enables users to upload card statements, categorize expenses, track income and savings, and visualize spending patterns through an intuitive dashboard. Key features include data anonymization, automated statement parsing, and goal-oriented savings tracking.

## 1. Design Approach

### 1.1 Architecture Overview

The application follows a modern three-tier architecture with a privacy-first approach:

- **Client Layer**: React-based single-page application (SPA) with responsive design, providing real-time data visualization and interactive dashboards
- **API Layer**: RESTful API built with Node.js/Express, handling authentication, data processing, and business logic
- **Data Layer**: PostgreSQL database with encryption at rest, implementing data anonymization strategies

### 1.2 Privacy-First Design

Data protection and anonymization are core architectural principles:

- **Encryption**: All sensitive data encrypted using AES-256 both in transit (TLS 1.3) and at rest
- **Data Minimization**: Only essential transaction metadata stored; merchant names and transaction details hashed or anonymized
- **Zero-Knowledge Processing**: Statement parsing occurs client-side where possible; server only receives aggregated, anonymized data
- **Data Isolation**: Multi-tenant database architecture with row-level security (RLS) ensuring users can only access their own data

### 1.3 User Experience Design

The interface prioritizes simplicity, speed, and actionable insights:

- **Dashboard-First**: Landing page displays key financial metrics at a glance (monthly spend, savings rate, budget progress)
- **Progressive Disclosure**: Summary views with drill-down capability for detailed transaction analysis
- **Smart Categorization**: ML-powered automatic expense categorization with manual override options
- **Goal Visualization**: Progress bars, charts, and projections for savings goals with milestone tracking

## 3. User Story Implementation

### 3.1 Story 1: Data Protection & Anonymization

**User Story**: *As a user, I want my data to be protected and anonymized*

**Implementation Approach**:

- **Authentication**: JWT-based authentication with refresh tokens, secure password hashing using bcrypt (12 rounds)
- **Database Encryption**: PostgreSQL pgcrypto extension for column-level encryption of sensitive fields (account numbers, transaction IDs)
- **Data Anonymization Pipeline**:
  - Merchant names hashed using SHA-256 with user-specific salt
  - Transaction IDs replaced with UUIDs
  - Exact transaction amounts rounded to nearest dollar for analytics (original stored encrypted)
- **File Upload Security**: Statements encrypted on upload, processed in isolated containers, and deleted after 24 hours
- **Row-Level Security**: PostgreSQL RLS policies ensuring users can only access their own data at the database level

### 3.2 Story 2: Upload Card Statements

**User Story**: *As a user, I want to upload my card statements and update the tracker*

**Implementation Approach**:

- **Upload Interface**: Drag-and-drop file upload component supporting PDF and CSV formats, with multi-file upload capability
- **File Processing Pipeline**:
  1. File validation: Check format, size limits (max 10MB), and scan for malware
  2. Upload to S3 with server-side encryption
  3. Enqueue processing job in Bull Queue
  4. Worker process: Extract text using pdf-parse or csv-parser
  5. Transaction parsing using regex patterns for common statement formats
  6. Auto-categorization using TensorFlow.js model
  7. Deduplication check against existing transactions
  8. Insert into database and notify user
- **Statement Format Detection**: Support for major banks (Chase, Bank of America, Wells Fargo, Citi, Capital One) with adaptive parsing based on detected format
- **Real-time Status**: WebSocket connection providing live upload and processing status updates
- **Error Handling**: Manual review interface for transactions that fail auto-categorization or parsing

### 3.3 Story 3: Dashboard Summary

**User Story**: *As a user, I want a dashboard to see a summary of my expenses*

**Implementation Approach**:

- **Key Metrics Cards**:
  - Total spending this month (with comparison to last month)
  - Average daily spending
  - Largest expense category
  - Days until next payday / budget refresh
- **Visualizations**:
  - Spending trend line chart (last 6 months)
  - Category breakdown pie chart
  - Week-over-week comparison bar chart
- **Recent Transactions**: List of last 10 transactions with quick categorization editing
- **Budget Alerts**: Warnings when approaching spending limits in any category
- **Time Period Selector**: Toggle between daily, weekly, monthly, and custom date range views

### 3.4 Story 4: Category Spending

**User Story**: *As a user, I want to see how much I spent in each category*

**Implementation Approach**:

- **Default Categories**: Groceries, Dining, Transportation, Housing, Utilities, Entertainment, Shopping, Healthcare, Personal Care, Travel, Other
- **Category Management**:
  - Create custom categories with color coding
  - Set monthly budget limits per category
  - Merge or rename categories
- **Category View**:
  - Table view with category name, amount spent, budget, remaining, and percentage
  - Sortable by amount, percentage, or alphabetically
  - Drill-down to see all transactions in a category
- **Auto-Categorization Model**:
  - TensorFlow.js model trained on merchant name patterns
  - Learns from user corrections to improve accuracy
  - Confidence score displayed, manual review for low-confidence categorizations
- **Bulk Actions**: Recategorize multiple transactions at once, set rules for automatic categorization

### 3.5 Story 5: Income & Savings Tracking

**User Story**: *As a user, I want to add my income and savings*

**Implementation Approach**:

- **Income Entry**:
  - Manual income entry form with date, amount, source (salary, freelance, investment, other)
  - Recurring income profiles (e.g., monthly salary auto-entries)
  - Income categorization for tax tracking
- **Savings Accounts**:
  - Multiple savings account tracking (emergency fund, vacation, home down payment, etc.)
  - Manual balance updates with transaction history
  - Interest calculation support
- **Net Worth Calculator**: Dashboard showing total income minus total expenses and current savings balance
- **Savings Rate**: Automatic calculation of monthly savings rate (savings / income), with historical trends

### 3.6 Story 6: Savings Goals

**User Story**: *As a user, I want to track my savings and set goals*

**Implementation Approach**:

- **Goal Creation**:
  - Set goal name, target amount, and target date
  - Upload optional goal image for motivation
  - Priority ranking for multiple goals
- **Goal Tracking**:
  - Progress bar showing current savings vs. goal
  - Projected completion date based on current savings rate
  - Milestone notifications (25%, 50%, 75%, 100%)
- **Smart Recommendations**:
  - Suggested monthly contribution to reach goal by target date
  - What-if scenarios (e.g., if you save $100 more per month)
  - Identify spending categories to reduce to accelerate goal achievement
- **Goal Allocation**: Ability to allocate savings deposits to specific goals, view contribution history per goal
- **Gamification**: Achievement badges for hitting milestones, streak tracking for consistent savings

## 4. Implementation Concerns & Risk Mitigation

### 4.1 Security & Privacy Concerns

| Concern | Risk Level | Mitigation Strategy |
|---------|-----------|---------------------|
| Data breach exposing financial data | **HIGH** | Multi-layer encryption, database-level RLS, regular security audits, penetration testing, bug bounty program |
| Insufficient data anonymization allowing user re-identification | **MEDIUM** | Use k-anonymity principles, implement differential privacy for aggregated analytics, avoid storing unnecessary PII |
| Session hijacking or XSS attacks | **MEDIUM** | HttpOnly cookies, SameSite=Strict, CSP headers, input sanitization, React's built-in XSS protection |
| Malicious file uploads (malware in statements) | **MEDIUM** | ClamAV virus scanning on upload, sandboxed processing environment, file type validation, size limits |

### 4.2 Statement Parsing Challenges

| Challenge | Impact | Solution |
|-----------|--------|----------|
| Inconsistent statement formats across banks | High parsing failure rate, poor user experience | Build template library for top 20 banks, implement fallback OCR using Tesseract.js for unknown formats |
| PDF statements with complex layouts or scanned images | Text extraction failures | Use pdf.js for layout analysis, Tesseract.js for OCR, provide manual CSV upload as alternative |
| Duplicate transaction detection (same amount, same day) | Inflated expense totals, data integrity issues | Multi-field matching (date, amount, merchant hash), fuzzy matching with confidence thresholds, user confirmation for potential duplicates |
| International transactions with currency conversion | Inaccurate spending totals without conversion | Use Open Exchange Rates API for historical conversion, store both original and converted amounts |

### 4.3 Scalability Concerns

| Bottleneck | Threshold | Scaling Strategy |
|------------|-----------|------------------|
| Statement processing queue backlog | 1000+ concurrent uploads | Horizontal scaling of worker processes, implement priority queue for premium users |
| Database query performance on large transaction datasets | 10M+ transactions | Implement table partitioning by month, add indexes on user_id + date, use read replicas for analytics queries |
| Dashboard load time with years of data | >3 seconds for initial load | Implement aggregation materialized views refreshed nightly, use Redis caching for frequently accessed metrics, lazy load older data |
| API rate limiting concerns for external services | Currency API: 1000 calls/mo free tier | Cache exchange rates daily, batch requests, implement fallback to secondary provider |

### 4.4 User Experience & Data Quality

- **Auto-categorization Accuracy**: Initial ML model may have 60-70% accuracy. Mitigation: Implement active learning where user corrections retrain model, provide bulk recategorization tools, show confidence scores.
- **Complex Onboarding**: Risk of user abandonment during setup. Mitigation: Progressive onboarding, allow skipping optional steps, provide sample data for demo mode.
- **Mobile Responsiveness**: Charts and tables may be difficult on small screens. Mitigation: Mobile-first design approach, touch-optimized interactions, simplified mobile views.
- **Data Export & Portability**: Users may want to leave platform. Mitigation: Provide CSV/JSON export functionality, document data schemas, implement GDPR-compliant data deletion.

### 4.5 Compliance & Legal

- **GDPR Compliance**: Must implement right to access, right to deletion, data portability, explicit consent. Requires legal review and DPO appointment.
- **Financial Data Regulations**: Depending on jurisdiction, may fall under financial services regulations (PSD2 in EU, Gramm-Leach-Bliley in US). Requires compliance audit.
- **Terms of Service & Privacy Policy**: Must clearly disclose data usage, anonymization practices, third-party services (S3, Redis, analytics). Requires legal counsel review.
- **Audit Logging**: For compliance, implement comprehensive logging of data access, modifications, and deletions with tamper-proof storage.

## 6. Success Metrics

The following metrics will be tracked to measure product success:

- **User Engagement**: Daily active users, average session duration, statement upload frequency
- **Data Quality**: Statement parsing success rate (target: >85%), auto-categorization accuracy (target: >80% after user training)
- **User Satisfaction**: NPS score (target: >40), feature adoption rates, user retention after 30/60/90 days
- **Technical Performance**: API response time (target: <200ms p95), dashboard load time (target: <2s), zero security incidents
- **Goal Achievement**: Percentage of users who create savings goals, percentage who achieve goals, average time to goal completion
